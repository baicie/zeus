## 3. 一个真实的溯源缺陷（新 P0）

**Admin 与 Playground 的 `uiCommit` 是错的。**

| 项                     | 值                                                                |
| ---------------------- | ----------------------------------------------------------------- |
| 记录值                 | `ffde5592`（2026-11-09，UI #132）                                 |
| 冻结 UI SHA            | `89fc93ca`（2026-11-14，UI #146）                                 |
| 相差提交数             | **15**                                                            |
| 该区间内的 UI 源码改动 | `packages/primitives/dialog/src/dialog.tsx`（418 行）等 13 个文件 |

**根因**（`admin-image.yml:100-119`、`playground-image.yml:103`）：

```yaml
- name: Resolve the paired zeus-ui commit
  env:
    CONFIGURED: ${{ vars.ZEUS_UI_COMMIT }}
  run: |
    sha="${CONFIGURED:-}"
    case "$sha" in
      *[!0-9a-f]* | '')
        sha="$(gh api "repos/.../zeus-ui/commits/${sha:-main}" --jq '.sha')"
        ;;
    esac
```

`vars.ZEUS_UI_COMMIT` **在仓库里不存在**（已核实 `gh api repos/baicie/zeus/actions/variables`，无此变量）。于是它每次都去解析 UI `main` 的**当前** SHA。

`demos-pages.yml` 走的是另一条路径（`git fetch --depth 1 origin "${UI_REF}"`，`UI_REF` 默认 `main`），它的日志显示实际用的是 `89fc93ca`——**正确**。

**所以两个工作流对同一件事给出了不同的答案。**

## 4. 当前产物是对的吗？——是，但是运气

本轮直接检查线上 Admin 的 dialog chunk：

```
GET https://admin.moonbyte.top:8443/assets/zw-dialog.entry-BTrmj2FO.js
  → 4 908 B
  → "consumed-escapes"  1 处
  → "dialog/state"      1 处
```

**修复确实在线上。** 因为 `examples/admin` 消费的是 `vendor/zeus-web-dialog`（固定内容），与 UI commit 无关；`uiCommit` 只影响 `zeus-compat` 等通过 workspace 解析的包。

但这是一条**脆弱的运气**：

- `build-info.json` 说「这个镜像对应 UI `ffde5592`」，而 `ffde5592` 里的 dialog **不含修复**；
- 任何人拿 `ffde5592` 去重建，会得到一个**没有修复**的 Admin；
- 溯源链条在当前状态下是假的。

## 5. 为什么这是 P0

RC 的定义要求「这个 RC 对应哪两次提交、哪些实际构建产物」。当前生产镜像：

- Core commit：正确（`69f494f2`）
- UI commit：**错误**（记录 `ffde5592`，实际应是 `89fc93ca` 或「不适用，因为用的是 vendor」）
- artifactDigest：与记录一致（自洽）

**它不能回答「哪些实际构建产物」**，因为记录的 UI 提交与实际打入的组件不是同一份代码。

## 7. 修复建议（需授权）

按最小改动排序：

1. **给 Admin 与 Playground 的 build-info 增加 `vendoredDialog` 字段**，记录 vendor 的 `commit` 与 `contentDigest`。这样溯源不再只依赖 `uiCommit`。
2. **把 `vars.ZEUS_UI_COMMIT` 设为配对 SHA**，或在工作流里改为从 `demo-pairing.json` 读取，与 `demos-pages.yml` 用同一来源。
3. 在 RC 清单里显式写明：Admin 的 UI 依赖来自 `vendor/`，不来自 `uiCommit`。

第 1 条最重要——它让「记录是真的」这件事不再依赖一个未配置的变量。
