### 3.1 `create-zeus` 模板必须同步三样东西

`scripts/release/create-zeus-versions.ts` 在 `afterVersion` 阶段运行，规则是：

- `@zeus-js/*` 模板 pin → 跟随 **Core 版本**（`vite-plugin` 除外，跟自己的 `package.json`）；
- `@zeus-web/*` 模板 pin → 跟随 `ZEUS_UI_VERSION`（未提供则不动）。

所以切版时 `create-zeus` **包版本不变**，但**模板内的 `@zeus-js/*` 与 `@zeus-web/*` pin 必须一起切到 `0.2.0-rc.0`**。`--check` 已接进 precheck，漏了会红。

## 4. Cargo 版本：不是缺陷

| 问题                      | 事实                                                                                                           |
| ------------------------- | -------------------------------------------------------------------------------------------------------------- |
| workspace 里有几个 crate  | 3：`zeus_compiler`、`zeus_compiler_node`、`zeus_compiler_wasm`                                                 |
| 哪些会发布到 crates.io    | **只有 `zeus_compiler`**（另两个 `publish = false`）                                                           |
| npm 侧版本从哪来          | `syncNativeLoader()` 在 `afterVersion` 用发布版本写 `packages/core/compiler-native/index.js` 与 `package.json` |
| 平台包版本从哪来          | 独立 `package.json`，当前 `0.1.1-beta.20`，与 npm 主包一致                                                     |
| Cargo 版本参与 npm 产物吗 | **不参与**。它在 `.node` 二进制内部，npm 只看 `package.json`                                                   |
| 所以是版本污染吗          | **不是**。是 crate 独立于 npm 的历史版本残留                                                                   |

**唯一推荐方案**：切版时把 `Cargo.toml` 的 `[workspace.package] version` 一并改成 `0.2.0-rc.0`，与 npm 同源。理由不是「现在不一致所以坏了」，而是「一个 RC 对应一个版本号」这条原则。**不改也不会让任何 npm 包产错版本**——这是本轮对上一份报告判据的降级：**它不是 NO-GO 的理由**。

## 5. peerDependencies

`30` 条，全部是 `@zeus-js/zeus` 且全部钉死 `0.1.1-beta.20`：每个 UI 组件对 Core 的**精确版本**依赖。

这不只是「需要一起升」——它意味着：

- Core 不发 `0.2.0-rc.0`，UI 的 `0.2.0-rc.0` 装上去 peer 就对不上；
- 发布顺序 **Core 先、UI 后，不可交换**；
- 不存在「只发 UI 一个包」的路径。

## 6. 发布顺序与依赖

```
Cargo workspace version
        ↓
Core 32 fixed packages  ──┐
        ↓                 │  exact peer
UI 46 packages  ←─────────┘
        ↓
vendor/zeus-web-dialog 替换为已发布版本
        ↓
consumers（create-zeus 模板 pin、examples）
        ↓
dist-tag 修复（三个首次发布的包会把 latest 指向 RC）
```

**没有 npm 循环依赖**：UI 单向依赖 Core。存在的只是**构建顺序**依赖——Core 仓的 `examples/admin` 引用 UI 的 24 个包，那是仓库内的开发依赖，不进入发布图。
