### 2.2 B-2：空选择即通过

```bash
$ ZEUS_AI_WORKBENCH_BROWSERS=nonexistent pnpm exec tsx -e "..."

```

四次真实触发路径：拼错的引擎名、只有逗号的值、空变量、请求的引擎未安装（缓存失效的 runner 上最可能出现）。

### 2.3 B-6：视觉门禁的两次静默跳过

修复过程本身暴露了这个缺陷的两种形态，都来自运行日志：

```text
# 第一次：BASE 为空
BASE:
changed files:
##[notice]visual gate skipped: no AI Workbench change

# 第二次：PR 被当作 push，只比了最后一个 commit
EVENT: push
changed files in the pushed commit range:
##[notice]visual gate skipped
```

`workflow_call` 不传递 `github.event.pull_request.base.sha`。第一次读成空串，`git diff "" HEAD` 无输出；第二次退回 `HEAD~1`，只覆盖最新一个 commit，一个只改 yml 的后续提交就藏掉了它之前的 Workbench 改动。

### 2.4 C-7：三引擎焦点实测

```text
chromium  IN:BUTTONConfirm IN:BUTTONCancel IN:BUTTONConfirm ...
firefox   IN:BUTTONConfirm IN:BUTTONCancel IN:BUTTONConfirm ...
webkit    OUT:INPUT OUT:INPUT OUT:TEXTAREA OUT:DIVName OUT:DIVTeam ...
```

WebKit 从第一次 Tab 就离开对话框。原因是陷阱只监听 panel 上的 `keydown`，而 Safari 在 panel 持有焦点后把 Tab 的 keydown 投递给文档中的下一个元素。

### 2.5 C-5 / C-6：正确代码无法通过 tsc

```text
src/pages/user.tsx(243,11): error TS2322: ... Property 'ref' does not exist on type 'DialogProps'.
src/pages/users.tsx(322,11): error TS2322: ... Property 'ref' does not exist on type 'DataGridProps'.
```

把 `prop:columns` 改成普通属性（为了过类型检查）后，DataGrid 渲染成空表：

```text
<div data-slot="data-grid-viewport" aria-rowcount="4" aria-colcount="0">
```

数组值经 attribute 只能变成字符串，组件读不到列定义。

### 2.7 E-3：切换语言会抛响应式错误

补齐语言断言后，`check:admin` 立刻失败：

```text
Error: expect(received).toEqual(expected)
+ "A reactive effect cannot synchronously update its own dependencies. Move the
   write to an event or a separate effect."
```

原因在 `examples/admin/src/app.tsx`：负责应用账号语言偏好的 effect 先读
`i18n.locale()`（这使它成为依赖），再调 `setLocale`——effect 同步写自己刚读过的依赖，
Zeus 直接抛错。这个 throw 落在设置页的语言切换上：写入触发 effect 重跑，重跑又看到不一致，
再写一次。

此前没有任何测试切换过语言，所以这个错误从未被看到。**R6-E 第 11 项要求验证的正是这件事。**

修法是排序而不是抑制：比较保留（它避免每次会话刷新都重写），但写入排到 effect 返回之后。
`queueMicrotask` 在绘制前执行，界面不闪烁；回调执行时重新读取偏好与当前 locale，
避免覆盖期间发生的会话更新。

### 2.6 D-1：按钮没有处理器

修复前 `main.ts` 中 `searchChatsButton` 的全部代码：

```ts
const searchChatsButton = el('button', 'wb-nav-item')
searchChatsButton.type = 'button'
searchChatsButton.dataset.testid = 'search-chats'
searchChatsButton.append(icon(ICONS.search), copy.text('workbench.searchChats'))
```

没有 `addEventListener`，全仓库也没有任何过滤逻辑。

### 7.3 放行判断

**R6-A / R6-B：可以放行。** 缺陷可复现、修复可证、测试覆盖了失败路径。剩下的是一次真实运行，那是合并后的事。

**R6-C：条件放行。** Gallery 现在展示的是真组件，三浏览器通过。但 C-8 / C-9 是真实的可用性缺陷——**一个读者关掉对话框就再也打不开它**。这在 Admin 的实际页面（`users.tsx` 的编辑对话框）里同样存在。建议：**RC 之前修，或至少在 RC notes 中明确列出**。

**R6-D：条件放行。** 搜索与着色是真功能。但"真实联网验收必须绑定最终发布候选 SHA"这一条**未完成**——它需要 environment 与 key。在那之前，R6-D 的验收只到 mock 网关为止。

**整体：不建议在 C-8/C-9 未解决、且 `Demos Pages` 未真实跑过一次的情况下宣布 0.2.0 RC 就绪。**

理由是这两项都属于"用户一用就会撞到"的问题：前者让 Admin 的编辑流程只能走一次，后者让 Demo 的来源仍然无法被第三方验证——而 R6-A 的全部工作正是为了让它能被验证。
