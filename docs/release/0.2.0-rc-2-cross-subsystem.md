## 4. 三项缺失的准确性质

`check:rc-readiness` 要求的是**一份组装完成的 `rc-evidence.json`**（v4），它由 `assemble-rc-evidence.ts` 从七个输入合成：

| 输入                          | 存在                   | 缺失原因                       |
| ----------------------------- | ---------------------- | ------------------------------ |
| `cross-platform`              | **有**（已下载并校验） | 未放进 `temp/release/`         |
| `pair.json`                   | 无                     | 需从一次真实发布 run 读取      |
| `deployment-acceptance.json`  | 无                     | 需 Stage 2 在线验收            |
| `deployment-transaction.json` | 无                     | 需一次真实部署事务             |
| `provenance.json`             | 无                     | 需 Stage 2 产出                |
| `approval.json`               | 无                     | `rc-approval.yml` **零次运行** |
| `trust.json`                  | 无                     | 随 approval 一起产生           |

**所以「cross-platform 缺失」与「release-approval 缺失」不是同一类问题：**

- cross-platform：**证据存在，只是没组装**。这是一步可以补的工作。
- release-approval：**证据不存在**。`rc-approval.yml` 的 `total_count` 是 0，`Release` 环境**没有任何保护规则**（`protection_rules: []`，`reviewers: []`）。
- online-products：**证据不存在**。没有 Stage 2 部署与事务记录。

维护者特别要求「不能把已有 CI success 自动视为已生成正式 cross-platform evidence」——本报告遵守：cross-platform 文档是从 artifact 取出的**正式产物**，不是把 CI success 当证据。
