## 1. Dialog 组件修复（zeus-ui#147）

### 1.1 撤回上一轮的错误根因

上一轮把 C-8 / C-9 记账为"`open` 反射成宿主属性后读回为 `true`，导致 Escape 不关闭、关闭后打不开"。
按这个机制复现不出来。三引擎实测（真实 Admin dist + 真实 server + Admin 实际安装的 beta.34）：

| 引擎     | 打开 | Escape           | 关闭按钮 | 遮罩 | 重开 ×3 |
| -------- | ---- | ---------------- | -------- | ---- | ------- |
| Chromium | ✓    | ✓                | ✓        | ✓    | ✓       |
| Firefox  | ✓    | ✓                | ✓        | ✓    | ✓       |
| WebKit   | ✓    | 仅焦点仍在面板内 | ✓        | ✓    | ✓       |

**原判定不成立，已在 `0.2.0-r6-integration-audit.md` §2.6 明确撤回。**

### 1.2 实际存在并已修复的缺陷

| #   | 缺陷                           | 机制                                                                                                                                                              | 证据                                                        |
| --- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 1   | 未受控对话框把自己变成受控     | `getOpen()` 每次重算 `props.open !== undefined`，而 `setOpen()` 先写 `ctx.host.open`——触发器第一次点击自己写出该 prop，下次读取即判为受控，从此只发事件不应用状态 | 修复前：受控分支 `open: false` 事件发出但 `data-state` 不变 |
| 2   | 受控对话框覆盖 owner 的值      | `setOpen` 无条件写 `ctx.host.open`                                                                                                                                | 修复前：owner 写 `false` 后组件又写回                       |
| 3   | 焦点移动只覆盖组件自身路径     | 焦点写在 `setOpen` 内，`el.open = true` / 路由恢复 / 受控重渲染都不搬焦点                                                                                         | 修复前：程序化打开后 `activeElement` 仍在面板外             |
| 4   | 投影重建后模式被重新推导       | 重建时 `props.open` 已是组件自己写的值                                                                                                                            | 修复前：`outer` 在重建后只发事件不关闭                      |
| 5   | WebKit 从 panel 按 Tab 跳 body | panel 自身 `tabindex="-1"` 持焦时 Safari 把焦点交给 body                                                                                                          | 修复前：`tab-forward` 后 `inPanel: false`                   |
| 6   | 一次 Escape 关掉整摞           | 各 bundle 各有自己的模块级状态                                                                                                                                    | 修复前：`changes: [inner:false, outer:false]`               |

**VERIFIED**：修复后 `pnpm check:dialog-interaction` 在三引擎上 18 步全绿。

## 2. Core #261：Admin 消费含修复的构建

### 2.1 做了什么

- `check:admin` 的 C-7 / C-8 / C-9 全部改为**阻断式断言**，WebKit 豁免已删除。
- 断言前先检查已安装的 `@zeus-web/dialog` 是否带修复标记（`Symbol.for('@zeus-web/dialog/state')`），
  缺失时**直接失败并指名原因**，而不是让读者看到一个深处的超时。
- 每个引擎额外输出 `temp/admin/gallery-<engine>.png`。
- 新增 `pnpm admin:link-dialog`：从相邻 zeus-ui 检出构建 dialog，连同 runtime peer 装进
  `examples/admin/node_modules`；`--restore` 用 pnpm 装回发布版。

### 2.2 验证矩阵

| 场景                             | 结果                                                                                                 |
| -------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 装本地修复构建 → `check:admin`   | **VERIFIED**：chromium / firefox / webkit 全绿，三张截图生成                                         |
| 装发布版 beta.34 → `check:admin` | **VERIFIED（预期失败）**：失败信息为 `@zeus-web/dialog in examples/admin must contain the state fix` |

### 2.3 失败过的方案（已回退）

把构建产物提交到 `vendor/` 并让 `examples/admin/package.json` 用 `file:` 引用。
本地三引擎全绿，**CI 失败**：`.gitignore` 忽略 `dist`，提交进去的只有 manifest，没有代码。
这是"只在 CI 暴露"的失败模式，正是本轮要消灭的，故整套回退，改为不写仓库的 link 脚本。

### 2.4 RC 阻塞

**BLOCKED**：`check:admin` 在 CI 上会红，直到发布一版含 `fix/dialog-state-and-focus` 的
`@zeus-web/dialog`。这不是 flake，也不应被弱化。发布后需要：

1. `examples/admin/package.json` 的 `@zeus-web/dialog` 改成该版本；
2. 删除 `pnpm admin:link-dialog`（或保留为本地调试工具，但 CI 不再依赖它）。
