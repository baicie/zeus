## 1. 四条已过期的结论

### 1.1 「PR #261 没有运行 `check:admin`」

**当时的记录**：`0.2.0-r6-final-acceptance.md:101` 写 `gh pr checks 261` 显示 11 项全过，
其中没有 `check:admin`。

**当时是对的**。`ci.yml` 当时写着 `pull_request: branches: [main]`，而 #261 的 base 是
`fix/r6-a-demo-pairing`，所以 PR CI 根本没启动。这一条是 R6 的真实发现。

**当前状态**：已修复并由测试守住。

```yaml
# .github/workflows/ci.yml
pull_request: # 不再有 branches 过滤
```

回归测试：`scripts/ci/__tests__/ci-workflow-triggers.spec.ts`。
证据：合并后 `69f494f2` 的 CI run `43568170593` 全绿，含 `packed-consumers`。

### 1.2 「CI `pull_request` 过滤导致堆叠 PR 不跑」

同 1.1，已修复。删除 `branches: [main]` 后，任意 base 的 PR 都会跑完整 CI。

### 1.3 「vendor 方案失败」

**当时的记录**：`0.2.0-r6-integration-audit.md:449` 与 `:523-531` 写把构建提交进
`vendor/` 的方案「已尝试并失败」，原因是 `.gitignore` 忽略 `dist`，提交进去的包只有
manifest 没有代码，CI 报 `Cannot find module '@zeus-web/dialog/wc'`。

**当时是对的，失败也是真的。** 根因是 git 的「最后匹配者胜」规则：
`dist` 规则写在例外之前，例外不生效。

**当前状态**：方案**已成功采用**，靠的是把例外写在 `dist` 之后：

```gitignore
dist
!vendor/zeus-web-dialog/dist/
!vendor/zeus-web-dialog/dist/**
```

```text
# .dockerignore，同样的顺序陷阱
**/dist
!vendor/zeus-web-dialog/dist
!vendor/zeus-web-dialog/dist/**
```

### 1.4 「Admin 仍使用 beta.34」

**当时的记录**：多处写 Admin 消费 `beta.34`，且该版本不含修复。

**当时是对的。** npm 上确实没有含修复的版本。

**当前状态**：Admin 消费 `vendor/zeus-web-dialog`（`0.1.0-beta.35`），**含修复**：

```json
// examples/admin/package.json:29
"@zeus-web/dialog": "file:../../vendor/zeus-web-dialog"
```

## 3. 本轮对 provenance 的加固

原 `verify-vendored-dialog.ts` 读取 `provenance.contentDigest` 并打印，**从未重算**。
记录的 `sha256:a45c3273…` 也不符合任何可复现算法——它是手写的。

本轮改动：

- 新增 `scripts/check/vendored-provenance.ts`，定义算法：
  sha256 over 按 path 排序的 `{path, sha256}` JSON；
- 69 个文件的摘要**全部正确**，只有 `contentDigest` 被替换为重算值；
- 新增 24 项对抗测试：文件被改、文件缺失、多出文件、漏记文件、摘要篡改、包名不符、
  版本不符、commit 非法、重复路径、路径穿越、符号链接、字节数漂移；
- 安装侧现在也会拒绝 vendored 构建没有的多余文件。

## 4. 当前 CI 的实际触发规则

| 工作流                 | push              | pull_request           | 部署                                   |
| ---------------------- | ----------------- | ---------------------- | -------------------------------------- |
| `ci.yml`               | `main`            | **任意 base**          | 否                                     |
| `admin-image.yml`      | `main`，15 类输入 | **同 push 的全部输入** | 仅 `push` + `refs/heads/main`          |
| `playground-image.yml` | `main`，12 类输入 | 同 push                | 仅 push + main                         |
| `demos-pages.yml`      | `main`            | —                      | 仅 push（`inputs.publish` 默认 false） |
| `compiler-native.yml`  | `main`            | 是                     | 否                                     |
| `rc-approval.yml`      | —                 | —                      | 受保护 environment                     |

**本轮修复**：`admin-image.yml` 与 `playground-image.yml` 各补了 4–6 类输入
（`vendor/**`、`scripts/**`、`.dockerignore`、`pnpm-workspace.yaml`、`tsconfig*.json`），
并把 `pull_request` 从「只监听 examples」改成与 push 一致。
回归测试：`scripts/ci/__tests__/image-build-inputs.spec.ts`。
