## 4. 失败点

Release Run `44447893463`：

```
pnpm release --publishOnly 0.2.0-rc.3 --tag rc --skipBuild
→ 第 8 个包 @zeus-js/compiler-native-linux-x64-gnu

npm error code TLOG_CREATE_ENTRY_ERROR
npm error error creating tlog entry - (409) an equivalent entry already
  exists in the transparency log with UUID 108e9186e8c5677ad6...
```

**关于 409 的成因：审计不能确认。** 一种可能是同一 tarball 此前已签名但未落库；另一种是 Sigstore 服务的重试语义。**没有 registry 侧证据能区分这两种**，因此不写结论。

可以确认的是：失败发生在**第 8 个包**，前 7 个已成功写入 npm，不可撤回。

## 5. 恢复路径评估

### 幂等性：**可行**

`@baicie/release` 的 `publishOnePackage` 默认 `skipExisting: true`：

```js
const skipExisting = options.skipExisting ?? publishConfig.skipExisting ?? true
if (skipExisting && (await npmVersionExists(config, pkg, options))) {
  console.log(`skip existing ${pkg.name}@${pkg.version}`)
  return
}
```

重跑同一个 `v0.2.0-rc.3` tag 的 Run 会跳过已发布的 7 个包，从第 8 个继续。

### 但有两个前置条件

1. **TLOG 409 必须先解决。** 若根因是"条目已存在"，重试会在同一包上持续失败。这需要 npm/Sigstore 侧的排查，不是仓库能修的。
2. **`compiler-native-linux-x64-gnu` 的 tarball 内容必须与已签名条目一致。** 不一致会产生两个不同的 tarball 声称同一版本。

### 不允许的恢复方式

- 发布 `0.2.0-rc.4` 来"覆盖" rc.3 —— `bootstrap-eligibility` 明确拒绝部分发布的恢复
- 删除已发布的 7 个包 —— 违反 CI 门禁且 npm 不允许同版本重发
- 手工 `npm publish` 单包 —— 绕过 provenance 与发布顺序

## 6. 安全恢复顺序

**前置**：TLOG 409 根因确定，且判定为可重试。

1. 确认 `v0.2.0-rc.3` tag 仍指向 `649e2f60`（不可变，不需操作）
2. 确认工作树在 `649e2f60` 且干净
3. 重跑 Release Run 的 `release` job（`skipExisting` 会跳过 7 个已发布包）
4. 观察第 8 个包是否仍 409
5. 若通过，25 个包依次发布；`github-release` 与 `compiler-registry-smoke` 会随后执行
6. 验证 `release:verify:published` 对 32 包全部通过

**停止条件**（任一满足即停止，不重试）：

- 同一包连续 2 次 409
- 任一包出现 `EPUBLISHCONFLICT`（版本已存在但内容不同）
- `skipExisting` 未生效（出现"已发布包被重新发布"的日志）
- 发布过程产生新的部分状态（已发数 ≠ 7 + 本次成功数）
