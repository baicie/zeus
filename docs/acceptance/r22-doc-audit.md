## 3. 写检查时我自己错了两次

两次都留在测试注释里，因为它们说明了「数字为什么容易错」：

1. `emit.rs` 的 47 个定义里 **44 个缩进一个空格**，锚定 `^fn` 的正则只找到 3 个；
   第一次算出 47 是因为用了别的口径，两次口径不一致才暴露问题。
2. **macOS 的 grep 不支持 `\w`**，`grep -oE "^fn \w+"` 静默返回 1。

现在用 JS 读文件，不用 shell 正则。

---

## 4. 一处「看起来会错但其实对」的地方

`emit.rs` 的 47 个函数里只有 3 个在行首，44 个缩进一格。这不是格式问题——
文件里有一个外层 `impl` 包裹。任何按行首锚定的统计都会严重少算。

**这也是为什么「个数」这类断言必须按实际源码结构写正则，而不是凭直觉。**
