## 5. 候选缺陷与新发现

### 5.1 设计包列出的 M0 候选

1. **set trap 误通知**（`packages/core/signal/src/baseHandlers.ts:178-189`）：`Reflect.set` 返回 `false` 时仍然 `trigger`。已复现，修复在本地分支 `fix/signal-failed-set@8efeb7a`（对齐 `@vue/reactivity` 3.5.44，附 60 行回归测试），未合并。交给 PR-04。
2. **内部 scheduler 丢任务**（`packages/core/signal/src/scheduler.ts:22-29`）：某个 job 抛错后，`finally` 中的 `queue.clear()` 丢弃同一轮后面所有 job，之后的 flush 也不会再执行它们。本轮对构建产物复现：

   ```sh
   node -e 'const { queueJob } = require("./packages/core/signal/internal.cjs"); const log = []; process.on("uncaughtException", e => log.push("uncaught:" + e.message)); queueJob(() => log.push("a")); queueJob(() => { throw new Error("boom") }); queueJob(() => log.push("c")); setTimeout(() => { console.log(JSON.stringify(log)); queueJob(() => log.push("d")); setTimeout(() => console.log(JSON.stringify(log)), 0) }, 0)'
   # 输出（exit 0）：
   # ["a","uncaught:boom"]          第一次 flush 后，c 被丢弃
   # ["a","uncaught:boom","d"]      之后的 flush 只执行新排队的 d
   ```

   `nextTick()`（`scheduler.ts:32-34`）只是 `Promise.resolve()`，不等待 flush；它在 job 之后 resolve 只是因为调用顺序。`queueJob/flushJobs/nextTick` 只从 `src/internal.ts:51` 导出，仓库内没有运行时调用方（`watch.spec.ts` 用自己的测试 scheduler），公开 `createEffect` 同步语义不受影响。按设计包要求“先查真实调用者”，本轮未修改，交给 PR-04 决定修复还是删除。

3. **`docs/guide/choosing-zeus.md:68-70` 过时措辞**：仍写“Zeus SSR currently renders HTML without hydrating that markup”，与已支持的显式 hydration 冲突。修正在本地分支 `docs/guide-hydration-wording`，未合并。`check-docs.ts` 只检查标题和链接，不能发现这类事实错误。
4. **LICENSE / NOTICE**：事实见第 2 节“许可”行。审计与结论由 PR-03 负责。
5. **AI 包 `private` + `publishConfig`**：属于 Zeus UI，由 PR-02 负责。

### 9.1 WASM 编译器（PR-08）
