## 0. 目标、非目标与完成定义

### 北极星目标

1. **Zeus Native**：用标准 TSX 开发真实 CSR 应用；compiler-first、fine-grained DOM，不靠组件 rerender/VDOM 兜底。
2. **Zeus WebC**：一份 TSX 组件源码，产出 Web Components + React / Vue 的类型安全适配包；核心行为只实现一次。
3. **工程可信**：外部项目能够 `create → develop → test → build → pack/install → publish/use`，不依赖 monorepo 内部路径和私有 API。
4. **保持稳定**：继续使用当前 Rust Compiler、Signal、DOM Runtime、Component Compiler Host；协议修复优先于新增语法糖。

### 范围排除（当前四个里程碑不做）

- 不重写 Rust Compiler 或全面迁移为另一种编译器。
- 不为了使用 `alien-signals` 而直接替换正在工作的响应式核心；先审计与验证。
- 不开发 Next.js 类 Meta-framework、全量 Router/Query/Forms 基础设施。
- 不承诺任意 React Element / Vue VNode 可以直接作为 WC 的内部 JSX 运行。
- 不在 TSX 兼容性和 ABI 收敛之前推出 `$state` 公共稳定 API。
- 不以“组件数量”作为成熟度指标。

### Done 的统一要求

- [ ] 代码变更有最小复现、单测或端到端验证；纯规范任务有可审阅 RFC 和测试计划。
- [ ] 类型检查、lint、相关单测、生产构建通过；有语义变更时同时覆盖 SSR/浏览器分支。
- [ ] 任何公共 API/生成结果变更同步修改 Manifest、DTS、文档、CHANGELOG、Snapshot。
- [ ] 与 `zeus-ui` 的 canary 对齐/兼容回归通过；重要的发布改动经过 `npm pack` 外部消费测试。
- [ ] 破坏性变更必须有迁移策略、诊断警告与至少一个版本窗口，不在补丁版本静默改变语义。

## 7. 测试矩阵与质量阈值（跨所有里程碑）

| 类别 | 必测场景 | 通过要求 |
|---|---|---|
| Reactivity | 依赖变化、diamond、batch、scope/dispose、async race | 无丢更新/孤儿 effect |
| Compiler | 标准 TSX、Spread、Nested JSX、SVG、异常诊断、Source Map | 运行行为正确，诊断稳定 |
| WC | Property vs Attribute、默认值、表单、Slot、reconnect、lazy | eager/lazy 对齐 |
| Framework | React18/19、Vue3、SSR Import | Typecheck + Browser E2E |
| Browser | Chromium、Firefox、WebKit | 功能契约通过 |
| Package | `npm pack`、exports、CSS、peer、tree shaking | 无 monorepo-only 依赖 |
| UI | A11y、Keyboard、Focus、Data Grid | 关键交互通过 |
| Performance | Compile、Cold Start、JS Gzip、DOM 写入、长列表 | 与冻结基线对比，无未经批准回退 |

### Golden Scenario 编号

- **G-01**：Counter — primitive Signal、DOM text、Event、dispose。
- **G-02**：Input — value/default/controlled、change Event、focus、Form。
- **G-03**：Dialog — Slot/Portal/keyboard/focus、disconnect/reconnect。
- **G-04**：Data Grid — 10k/100k 行、列虚拟化、selection/sort、focus。
- **G-05**：React/Vue — Object Property、CustomEvent Detail、named slots、SSR import。
- **G-06**：Compiler — Spread、conditional JSX、array children、function-valued props。
- **G-07**：Lazy — before upgrade/connected/loading/ready/detached 多阶段状态。
