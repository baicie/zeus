# RFC-009：Beta API 与稳定性边界

- 状态：采纳
- 日期：2026-10-17
- 任务：B-004

## 决策

Zeus 的 `0.1.x-beta` 及后续尚未宣布稳定的版本采用唯一当前契约。版本号升级到 `0.2.0` 本身不等于全部 API 稳定；稳定范围必须在发布说明中明确列出，并由契约测试和独立消费者验证支撑。

Beta 阶段改变接口时，同一改动直接迁移仓库内源码、生成器、示例、测试、类型和文档，删除旧接口。没有旧接口 alias、双格式分支、legacy 配置、弃用窗口或兼容转发包。设计提案中的弃用窗口不适用于当前项目。

明确支持的 React 18/19、Vue 3、Node、浏览器、ESM/CJS 和真实 peer dependency 是平台契约，必须继续验证。它们不属于可以删除的历史 Zeus 设计。

## 契约分层

| 范围                | 约束                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| 应用公共 API        | `@zeus-js/zeus` 及明确公开的子入口，以发布声明、文档和消费者测试为依据                               |
| WC 产物 API         | Analyzer 元数据驱动的 property、attribute、event、method、slot、注册入口，以组件声明和行为测试为依据 |
| 编译器/框架内部接口 | IR、DOM/SSR helpers、`signal/internal` 可随实现演进；生成器和运行时必须同时更新                      |
| 计划中能力          | RFC 或路线图不是已支持声明；未通过验收的 hydration、框架 renderer、表单等不得承诺可用                |

## CI API Diff Gate

现有 CI 的 `build` job 依次执行 `pnpm build`、`pnpm build-dts` 和 `pnpm api:check`。快照从每个已发布包的 `exports` 中的声明入口生成，保存于 `docs/api/snapshots/`，包含新增与移除的子入口。

`api:check` 重新生成快照，检查相对声明引用，并拒绝未登记的快照差异、删除和未跟踪文件。开发者有意改变契约时执行 `pnpm api:snapshot`，将快照与实现、测试和文档一起交给代码审查。快照只证明声明变化被审查，不能替代运行时兼容性证明。

CI 同时运行 `check:cjs`、`check:exports`、类型检查及单元测试。独立 tarball 消费者矩阵另行验证 Native、React 18/19、Vue 3 的安装、类型、生产构建、SSR 与浏览器行为；这些检查通过前不能把接口变更视为验收完成。

## 宣布稳定的条件

某项 API 宣布稳定前，应具有明确的输入、输出、错误和释放语义，源码与发布产物一致，并通过其支持平台的契约测试。WC 还需验证 eager/lazy 生命周期、升级前写入、反射、事件、slot 和 ready 语义。对尚无证据的范围继续标记实验性，不能仅凭导出存在或快照更新宣布稳定。
