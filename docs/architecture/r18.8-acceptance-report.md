## 本次交付：PR #351

**Base** `63f40135` → **HEAD** `049630d8`。

### TASK 01 — RuntimeNames 所有权 [VERIFIED]

**复现的真实问题**：`dom/emit.rs` 引用 `crate::codegen::RuntimeNames`，形成
`codegen::dom::emit -> codegen` 的反向依赖。

**测量**：`RuntimeNames` 在 `dom/emit.rs` 出现 34 次、`codegen/mod.rs` 7 次；
SSR 有独立的 `SsrRuntimeNames`，从不使用它。DOM 专属资源。

**修复**：连同 `HelperUsage` 与 7 个 `collect_*_helper_usage` 移入
`codegen/dom/names.rs`。`allocate` 跟着类型走——它接受 `&HelperUsage` 和
`&mut NameAllocator`，拆开会把命名顺序契约从定义处挪走。

**旧依赖图 → 新依赖图**：

```
旧：codegen::dom::emit -> codegen
新：codegen::dom::emit -> {codegen::dom, codegen::infra, ir, support::hydration}
    codegen -> {..., codegen::dom::emit, codegen::dom::names, ...}
```

**公开行为**：45 golden 字节一致，SourceMap 未变，`NameAllocator` 分配顺序未变。

### TASK 02 — 最深模块归因 [VERIFIED]

**修复**：`resolve_use` 对裸根路径返回完整候选，由前缀遍历截断到最长真实模块。

**边图**：55 → 66 条。多出的是以前被折叠到父模块的子模块边。

**顺带发现的缺陷**：前缀遍历会停在写下该路径的模块本身，把
`use nowhere::thing` 变成 `a` 上的自环并静默通过。已修复并加测试
`an_edge_to_a_module_that_does_not_exist_is_reported`。

### TASK 03 — 单向依赖契约 [VERIFIED]

## 结论

**Zeus 当前不具备对外 Beta 产品能力。** 原因不是编译器质量，是**产品侧验收大面积 BLOCKED**：

- 能证明的：编译架构边界可信（M1 的 P0 三项）、Native/WASM 输出一致、包导出正确、脚手架可用。
- 不能证明的：浏览器里的 DOM 精确更新、SSR→hydration 复用、HMR 生命周期、
  Web Components 清理。这些是框架的核心承诺，而它们目前**只有 CI 的间接绿灯**，
  没有本任务要求的直接断言。

**真正阻塞发布的**：TASK 09–13。没有这些证据，"细粒度响应式 + 精确 DOM 更新"
就仍是一句设计声明。

**可以后置的技术债**：`Lowerer` 的强连通分量、`dom/emit.rs` 的 1789 行——
已测量、已记录、不影响正确性。

**下一步应聚焦**：在一个能装 Playwright 的环境里完成 TASK 09–13，
那是从"编译正确"到"框架可用"的唯一路径。
